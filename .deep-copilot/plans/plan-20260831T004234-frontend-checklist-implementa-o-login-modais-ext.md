## 目标 / Goal
Implementar o fluxo funcional do frontend: login real, criação de conta via modal, extrato mínimo (saldo + histórico + FAB "+") e movimentação única (depósito/saque) via modal com contraparte opcional por CPF ou número de conta — usando a paleta oficial já aplicada e o backend pronto (incluindo a resolução por número de conta da ADR 0003). Produzir e manter um checklist (docs/FRONTEND_DEV_CHECKLIST.md) no estilo do da API, para controlar as fases.

## 方案 / Approach
Seis fases em sequência, espelhando o estilo do API_DEV_CHECKLIST.md: (0) ADR 0004 com as decisões de arquitetura + aprovação; (1) infra de API e sessão (api.ts + AuthContext + login real); (2) Modal base + máscaras + CreateAccountModal; (3) ExtratoPage mínimo (saldo + lista + FAB); (4) MovementModal único (depósito/saque, "Pra quem?" CPF|conta, idempotência); (5) validação final no Docker + docs. Sem react-router (troca por estado), sem framework de testes (build + lint + fluxo manual), reaproveitando tokens da paleta já existentes (balance-bg, income, expense) e o proxy /api já configurado.

## 风险与缓解 / Risks
- CORS/roteamento em dev: mitigado pelo proxy /api já configurado (Vite → porta 80).
- Token expira (120 min): 401 tratado com logout automático.
- Replay de tecla/duplo clique: idempotência por crypto.randomUUID() por tentativa.
- Máscaras (CPF/valor/conta) mantidas simples e locais (lib/masks.ts), sem libs externas.
- Sem framework de testes no frontend: risco coberto por build/lint + checklist de fluxo manual.
