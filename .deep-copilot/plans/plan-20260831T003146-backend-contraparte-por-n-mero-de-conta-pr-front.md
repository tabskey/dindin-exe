# Backend: contraparte por número de conta (pré-front)

> Generated by Deep Copilot · Plan mode
> 2026-08-31T03:31:46.245Z

## 目标 / Goal
Permitir que o futuro modal de depósito do frontend identifique a contraparte por número de conta (além de CPF). Mudança mínima e aditiva no backend — hoje o contrato de movimentação só aceita counterpartyCpf e o MovementService só resolve por CPF. Ao concluir, o usuário commita antes de iniciarmos o frontend (o usuário faz os commits; o agente só sinaliza prontidão e fornece a mensagem).

## 方案 / Approach
Aditivo no contrato, sem migração de schema: (1) novo campo opcional CounterpartyAccountNumber em CreateMovementRequest; (2) IAccountRepository/AccountRepository ganham GetByAccountNumberAsync; (3) MovementService resolve por número (precedência) → por CPF → auto-depósito; (4) o label reutiliza CounterpartyLabel.For (mascara o CPF da conta encontrada — sem mudança de semântica); (5) Account ganha SetAccountNumber internal só para testes (padrão já usado por SetId/SetBalance); (6) testes unitários (label por número, número inexistente) + 1 teste de integração via API; (7) docs: ADR 0003, README (1 linha), AGENT_LOG.

## 步骤 / Steps
1. **DTO: adicionar CounterpartyAccountNumber** — Requests.cs — CreateMovementRequest ganha parâmetro opcional após CounterpartyCpf (compatível com chamadas posicionais existentes).
2. **Repositório: GetByAccountNumberAsync** — Interface IAccountRepository + implementação EF (AsNoTracking FirstOrDefault por AccountNumber) + FakeAccountRepository nos testes.
3. **MovementService: resolução por número** — Se CounterpartyAccountNumber não-vazio → resolve por número (trim); senão CPF; senão auto-depósito. Não encontrado → CounterpartyNotFound (400).
4. **Account.SetAccountNumber + comentário CounterpartyLabel** — Setter internal para os testes (padrão SetId/SetBalance); doc do CounterpartyLabel passa a citar resolução por CPF ou número.
5. **Testes: 2 unitários + 1 integração** — Unit: label por número ('JOAO TESTE 222-22 CC') e número inexistente mantém saldo. Integração: crédito com counterpartyAccountNumber de conta recém-registrada (AccountNumber lido via scope do AppDbContext) → 201 e label correto.
6. **Validação backend** — dotnet build 0 erros/0 avisos; dotnet test 108+ verdes (106 + 3 novos); dotnet format --verify-no-changes limpo.
7. **Docs: ADR 0003 + README + AGENT_LOG** — ADR 0003 (extensão do 0002, precedência número→CPF, label continua por CPF); README: regra de contraparte por número; AGENT_LOG: entrada da mudança.
8. **Avisar usuário para commitar** — Entregar mensagem de commit e aguardar o commit antes de iniciar o frontend (FAB + modal de movimentação).

## 风险与缓解 / Risks
- Label continua mascarando o CPF (não o número) mesmo quando a conta foi achada por número — comportamento uniforme, documentado no ADR; ajuste para máscara por número seria mudança posterior se desejado.
- AccountNumber não tem índice único no banco (geração aleatória 00xxx-xx) — colisão teórica; lookup usa FirstOrDefault; adicionar índice exigiria migração, fora do escopo mínimo.
- Precedência número→CPF→auto-depósito: se ambos vierem preenchidos, o número vence — documentado no ADR e no README.
- Sem migração EF: campo é só de request, sem mudança de schema.
